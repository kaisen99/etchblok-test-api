The search infrastructure in this project provides full-text search capabilities for bookmarks using an in-memory inverted index. It is designed for fast, token-based retrieval and relevance ranking, suitable for the small-to-medium datasets typical of a personal bookmarking tool.

The core of this functionality is implemented in `app/services/search_service.py` via the `SearchIndex` class, which is orchestrated by the `BookmarkService` to ensure the index remains synchronized with the underlying data repository.

## The Inverted Index

The `SearchIndex` class maintains an internal mapping of tokens to bookmark IDs. This structure allows for near-instant lookups of bookmarks containing specific words without scanning the entire database.

### Data Structure and Tokenization
The index is stored in a `defaultdict(set)` where each key is a string token and the value is a set of bookmark IDs:

```python
# app/services/search_service.py

class SearchIndex:
    def __init__(self, repository: "BookmarkRepository") -> None:
        self._repo = repository
        self._index: Dict[str, Set[str]] = defaultdict(set)
        self._rebuild()
```

Tokens are generated by the `_tokenize` method, which performs the following steps:
1.  Converts the input text to lowercase.
2.  Uses a regular expression (`[a-z0-9]+`) to extract alphanumeric tokens.
3.  Filters out common "stop words" (e.g., "the", "and", "is") defined in the `_STOP_WORDS` set to reduce index noise and improve relevance.

```python
# app/services/search_service.py

_STOP_WORDS: Set[str] = {"the", "a", "an", "and", "or", "but", "in", "on", "at", "to", "for", "is", "it"}
_TOKEN_RE = re.compile(r"[a-z0-9]+")

def _tokenize(self, text: str) -> List[str]:
    """Split text into lowercase tokens, removing stop words."""
    tokens = _TOKEN_RE.findall(text.lower())
    return [t for t in tokens if t not in _STOP_WORDS]
```

### Indexing Logic
When a bookmark is indexed via `index_bookmark`, the system combines the `title` and `description` fields into a single string for tokenization. Before adding new tokens, it removes any existing entries for that bookmark ID to prevent stale data during updates.

```python
def index_bookmark(self, bookmark: Bookmark) -> None:
    """Add or update a bookmark in the index."""
    self._remove_bookmark_from_index(bookmark.id)
    tokens = self._tokenize(f"{bookmark.title} {bookmark.description}")
    for token in tokens:
        self._index[token].add(bookmark.id)
```

## Search Execution and Ranking

The search process uses a strict **AND-logic** for multi-token queries. This means a bookmark must contain *all* tokens in the search query to be included in the results.

### Query Processing
The `search` method tokenizes the query and then performs a set intersection across the candidate IDs for each token:

```python
# app/services/search_service.py

def search(self, query: str, limit: int = 20) -> List[Bookmark]:
    tokens = self._tokenize(query)
    if not tokens:
        return []

    # Start with the set of IDs for the first token
    candidate_ids: Set[str] = self._index.get(tokens[0], set()).copy()
    
    # Intersect with sets for subsequent tokens (AND logic)
    for token in tokens[1:]:
        candidate_ids &= self._index.get(token, set())

    results = []
    for bid in candidate_ids:
        bookmark = self._repo.get_bookmark(bid)
        if bookmark:
            results.append(bookmark)

    return self._rank_results(results, tokens)[:limit]
```

### Relevance Ranking
Once the matching bookmarks are retrieved, they are ranked by the `_rank_results` method. The ranking algorithm is a simple frequency count: it calculates how many times the query tokens appear in the combined title and description of each bookmark.

```python
@staticmethod
def _rank_results(bookmarks: List[Bookmark], tokens: List[str]) -> List[Bookmark]:
    """Rank results by number of token occurrences in title + description."""
    def score(b: Bookmark) -> int:
        text = f"{b.title} {b.description}".lower()
        return sum(text.count(t) for t in tokens)

    return sorted(bookmarks, key=score, reverse=True)
```

## Service Integration

The `BookmarkService` (in `app/services/bookmark_service.py`) acts as a facade that coordinates the `SearchIndex` with the `BookmarkRepository`.

### Synchronization
The service ensures the index is updated during write operations:
- **Creation**: `create_bookmark` calls `self._search.index_bookmark(bookmark)`.
- **Updates**: `update_bookmark` re-indexes the bookmark after modifying its title or description.
- **Initialization**: When the `BookmarkService` is first instantiated (as a singleton), it initializes the `SearchIndex`, which in turn calls `_rebuild()` to populate itself from the repository.

```python
# app/services/bookmark_service.py

def _init_services(self) -> None:
    """Bootstrap repository, cache, and search index."""
    self._repo = BookmarkRepository()
    self._cache: LRUCache[Bookmark] = LRUCache(max_size=256)
    self._search = SearchIndex(self._repo)
```

## API Exposure

The search functionality is exposed via a GET endpoint at `/api/bookmarks/search`. It accepts a query string `q` and an optional `limit` parameter.

```python
# app/routes/bookmarks.py

@bookmarks_bp.route("/search", methods=["GET"])
def search_bookmarks():
    query = request.args.get("q", "")
    limit = request.args.get("limit", 20, type=int)
    results = _service.search(query, limit=limit)
    return jsonify({"results": [b.to_dict() for b in results], "count": len(results)})
```

## Design Tradeoffs and Constraints

The implementation makes several specific design choices that impact its behavior:

1.  **In-Memory Persistence**: The index is entirely in-memory. While this provides high performance, the index must be rebuilt from the repository every time the application starts. This is handled in `SearchIndex._rebuild`, which fetches all bookmarks from the repository.
2.  **Strict AND Matching**: The use of set intersection in the `search` method means that a query for "python tutorial" will not return bookmarks that only contain "python" or only "tutorial". Both must be present.
3.  **Soft-Deletion Behavior**: When a bookmark is "deleted" via `BookmarkService.delete_bookmark`, its status is changed to `TRASHED` in the repository, but it is **not** removed from the `SearchIndex`. Because `SearchIndex.search` retrieves the bookmark object from the repository to perform ranking, trashed bookmarks will still appear in search results unless the API consumer filters them by the `status` field in the response.
4.  **Scalability**: The `_remove_bookmark_from_index` method iterates over every token in the index to find and discard a bookmark ID. As the number of unique tokens grows, this operation becomes more expensive, making this implementation best suited for smaller datasets.
